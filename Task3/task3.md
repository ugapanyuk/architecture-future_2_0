# Дорожная карта трансформации IT-ландшафта «Будущее 2.0»

Этот план описывает последовательные шаги по переходу от устаревшей монолитной системы к современной доменной архитектуре.

## Этап 1. 3 месяца
**Бизнес-цель:** Устранить критические риски остановки бизнеса и подготовить базу для быстрой аналитики.

| Задача | Описание и Обоснование | Используемые технологии (из Радара) | Ответственные |
| :--- | :--- | :--- | :--- |
| **1. Развертывание Облака** | Подготовка защищенного облачного контура. <br>*Зачем:* Обеспечивает масштабируемость и надежность, которых нет у текущих серверов. | **Облачная Платформа**, Инструменты безопасности | Архитекторы, DevOps |
| **2. Создание Озера Данных** | Настройка дешевого хранилища для сбора "сырых" данных. <br>*Зачем:* Снимает нагрузку с операционной базы. Данные копируются туда, а не грузят систему врачей. | **Озеро Данных (Data Lake)**, Скрипты выгрузки | Дата-инженеры |
| **3. Изоляция Финтеха** | Выделение финансовых данных в отдельную защищенную зону в облаке. <br>*Зачем:* Критично с точки зрения безопасности. Исключает доступ врачей к банковской тайне. | **Доменная Архитектура**, Шина Событий | Команда Финтеха, ИБ |
| **4. Заморозка Монолита** | Запрет на добавление новой бизнес-логики в старую базу SQL Server. <br>*Зачем:* Останавливает рост технического долга. | **Методология**, Управленческое решение | CTO, Тимлиды |

**Результат этапа:** Данные надежно сохранены в облаке. Банковские данные отделены от медицинских.


## Этап 2. 3-6 месяцев
**Бизнес-цель:** Ускорить принятие решений за счет быстрых отчетов и запустить Портал самообслуживания (MVP).

| Задача | Описание и Обоснование | Используемые технологии (из Радара) | Ответственные |
| :--- | :--- | :--- | :--- |
| **1. Запуск Витрин Данных** | Создание готовых наборов данных для аналитики (отдельно медицинских, отдельно финансовых). <br>*Зачем:* Отчеты строятся за минуты на готовых витринах, а не часами на сырых данных. | **Витрины (Data Marts)**, Python (ETL) | Аналитики данных |
| **2. BI-Портал** | Внедрение BI-инструмента, где менеджеры сами строят графики. <br>*Зачем:* Снижает нагрузку на IT-отдел. Бизнес получает цифры мгновенно. | **Новый BI (Веб-портал)**, **Самообслуживание** | BI-разработчики |
| **3. Интеграция ИИ** | Подключение сервисов ИИ к Озеру Данных для обучения моделей. <br>*Зачем:* ИИ получает доступ к архивам снимков без рисков нарушения работы клиники. | **Python (ИИ)**, Озеро Данных | Data Scientists |

**Результат этапа:** Менеджеры сами строят отчеты в веб-портале. Время получения аналитики сократилось с часов до минут.

## Этап 3. 6–12 месяцев
**Бизнес-цель:** Подключение новых бизнесов (Фарма, Электроника) и полный отказ от старой логики.

| Задача | Описание и Обоснование | Используемые технологии (из Радара) | Ответственные |
| :--- | :--- | :--- | :--- |
| **1. API для Партнеров** | Создание стандартных шлюзов для подключения внешних компаний. <br>*Зачем:* Позволяет быстро подключить купленную сеть аптек или поставщика оборудования. | **Шина Событий**, Микросервисы | Бэкенд-разработчики |
| **2. Каталог Данных** | Внедрение "Википедии" по данным компании. <br>*Зачем:* Новые сотрудники и партнеры быстро понимают, какие данные есть в компании и где их взять. | **Каталог Данных**, Самообслуживание | Data Governance |
| **3. Вывод из эксплуатации** | Постепенное отключение старых процедур в SQL Server 2008. <br>*Зачем:* Снижение затрат на лицензии и поддержку устаревшего ПО. | **Избегать: Монолит DWH** | Системные администраторы |

**Результат этапа:** Экосистема готова к подключению любых новых бизнесов за 2-3 недели. Работает единый каталог данных. Старая система используется только как архив.
