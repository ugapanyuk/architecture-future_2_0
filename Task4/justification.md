# Обоснование конфигурации инфраструктуры (Yandex Cloud)

В данном решении реализована автоматизация развертывания инфраструктуры компании «Будущее 2.0» в Яндекс.Облаке с использованием подхода Infrastructure as Code (IaC).

## 1. Выбор ресурсов и параметров

### Виртуальные машины (Compute Cloud)
*   **Платформа `standard-v3` (Ice Lake):** Выбрана как современное и экономичное решение для задач общего назначения.
*   **Настройка `core_fraction = 20`:** Использование гарантированной доли CPU (20%) позволяет существенно снизить стоимость (burstable performance), что допустимо для тестовых сред и веб-портала с неравномерной нагрузкой.
*   **Прерываемые VM (`preemptible = true`):** Включена опция прерывания. Это снижает стоимость аренды в разы. Для среды разработки и тестирования риск перезагрузки раз в 24 часа приемлем.

### Сеть и Безопасность (VPC)
*   **Разделение на подсети:**
    *   **Публичная (Public):** Для Портала самообслуживания. ВМ имеет публичный IP (`nat = true`) для доступа пользователей из интернета.
    *   **Частная (Private):** Для сервера Обработки данных. ВМ не имеет публичного IP, что защищает её от внешних атак.
*   **NAT-шлюз:** Настроен для частной подсети. Это позволяет серверу Обработки скачивать обновления и библиотеки из интернета, оставаясь недоступным для входящих подключений извне.

### Хранение данных (Disks)
*   **Сетевой HDD (`network-hdd`):** Выбран для минимизации затрат.
*   **Отдельный диск:** Озеро данных (Data Lake) создается как отдельный ресурс `yandex_compute_disk`. Это обеспечивает сохранность данных даже при пересоздании или удалении самой виртуальной машины.

## 2. Преимущества Декларативного подхода (Terraform)

1.  **Воспроизводимость:** Описанная конфигурация позволяет развернуть идентичную копию инфраструктуры (например, для нового филиала или тестового стенда) одной командой `terraform apply`.
2.  **Управление состоянием:** Terraform отслеживает текущее состояние облака. Если кто-то вручную удалит подсеть, следующий запуск Terraform восстановит её.
3.  **Масштабируемость:** Для увеличения мощности сервера обработки достаточно изменить параметр `cores` или `memory` в коде, не переустанавливая систему вручную.
